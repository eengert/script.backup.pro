# Backup Pro design baseline

Status: AF3 capture, archive integration, restore preflight and file transaction
core complete; Kodi restore orchestration pending

## Product identity and boundaries

- Display name: Backup Pro
- Add-on ID: `script.backup.pro`
- Upstream baseline: Backup 1.7.3, commit
  `cdd8faf990e688e9ff522acd3375e90539ac49e7`
- Distribution: `repository.eengert` as a Program add-on
- Runtime entry points: Program action plus Service scheduling
- Coexistence: install alongside `script.xbmcbackup`; no shared settings or
  add-on-data directory
- Archive compatibility: Backup Pro is not required to restore archives made
  by standard Backup
- Test platform: disposable Kodi profile on this Mac
- Apple TV boundary: read-only inspection only; no installation, backup,
  restore, configuration, or other device write

## Initial user configuration to preserve

The representative standard Backup configuration on this Mac uses Simple
selection with Add-ons, Add-on Data, Database and Config enabled. Thumbnails,
Playlists, Profiles and Game Saves are disabled. Scheduling runs on the first
day of each month at 03:00 and catches up after a missed run. Backup Pro must
offer equivalent choices without silently importing or modifying the original
add-on's settings.

## Version 1 feature scope

### Measured backup plan

Before writing an archive, show total included bytes, category totals, largest
included directories and bytes omitted by each exclusion. The same information
must be written to the archive manifest. A cancelled preview must not create or
rotate a backup.

### TMDb Helper generated-image exclusions

The first adapter is limited to `plugin.video.themoviedb.helper`. It may omit
only these confirmed generated cache directories:

- `blur_v3`
- `crop_v2`
- `desaturate_v2`
- `colors_v2`

Resolve TMDb Helper's configured image location rather than assuming the
default add-on-data directory. Never exclude `settings.xml`, `players`,
`reconfigured_players`, `database_07`, arbitrary image extensions, or an
unrecognized path. Missing directories are normal. Exclusions are opt-in,
visible in the preflight summary and recorded in the manifest.

Path matching must be normalized and component-aware. Raw string-prefix
matching is insufficient because similarly named sibling directories must not
be excluded accidentally.

Restoring an archive with omitted caches must not delete an existing cache at
the destination. On a clean profile the cache may be regenerated by TMDb
Helper after use.

### Arctic Fuse 3 configuration adapter

The initial skin adapter supports `skin.arctic.fuse.3` and its managed
`script.skinvariables` source data. It must reuse the proven Skin Settings
Backup behavior rather than treating the active skin's on-disk `settings.xml`
as authoritative.

Required behavior:

1. Capture Kodi's live bool/string skin-setting map and encode a portable,
   validated settings document.
2. Include AF3 Skin Variables source JSON and viewtype data, not generated
   build products or build fingerprints.
3. Preview skin ID, source device/profile, versions, setting count and helper
   file count before restore.
4. Stop playback and switch away from the target skin before replacement.
5. Create durable pending state and a rollback snapshot before mutation.
6. Stage verified data through Kodi VFS while AF3 is inactive.
7. Reactivate AF3, rebuild its generated menus/widgets/views and verify live
   values plus helper hashes.
8. Clear pending state only after verification. Preserve recoverable state on
   cancellation, crash, skin-confirmation rejection or verification failure.

The adapter boundary must allow later support for other well-known skin helper
systems without weakening AF3 validation.

### Archive and restore safety

- Versioned manifest with normalized relative paths, file sizes and SHA-256
  hashes
- Duplicate member, traversal, absolute-path, symlink and unsupported-entry
  rejection
- Explicit file-count, member-size and total-size bounds
- Verified upload/read-back before publishing completion or running retention
- Durable restore phases and exact rollback data
- New operations blocked while recovery is unresolved
- No claim of success until post-restore verification passes
- Clear distinction between authoritative data and regenerable cache data

Broad file groups require group-specific restore policy. Databases, add-ons,
Kodi configuration and skin configuration must not be treated as one atomic
live-file copy without preflight and recovery planning.

## User experience requirements

- Direct, narrow-screen-friendly labels and Kodi-native dialogs
- Main actions: Back up now, Restore a backup, Settings, Help and Status
- Visible progress during scans, copies, uploads, skin changes and rebuilds
- Plain-language descriptions of inclusions, exclusions and expected cache
  regeneration
- Restore preview that names replaced groups and rollback availability
- Recovery actions shown before unrelated actions while state is pending
- Completion summary with counts, sizes, exclusions and verification results
- Background service never initiates an interactive skin switch

## Phased implementation and checkpoints

1. **Foundation (complete)**: fork, independent identity, design record, clean validation.
2. **Planning engine (complete)**: pure path model, size preflight, normalized exclusions,
   TMDb Helper adapter and unit tests.
3. **Archive format (complete)**: versioned manifest, checksums, bounded
   validation and compatibility handling for Backup Pro archives. Folder and
   ZIP publications are read back before completion; retention is blocked on
   copy, cancellation or verification failure.
4. **AF3 adapter (complete)**: stable live capture, managed helper files,
   preview metadata, verified archive integration and isolated tests using Skin
   Settings Backup behavior. Generic Add-on Data copies exclude the adapter's
   authoritative paths while this option is enabled.
5. **Transactional restore (in progress)**: durable file rollback, pending
   recovery, verified payload loading, canonical pending-state serialization,
   atomic local persistence, enforced crash-phase transitions,
   pre-mutation rollback handoff, preview/pending-state validation and
   failure-injection tests are complete. Kodi wiring, VFS staging, AF3
   activation/rebuild and end-to-end verification remain.
6. **Scheduling and UX**: preserve current scheduling, integrate previews,
   status, cancellation and recovery-focused menus.
7. **Mac validation**: compile/package checks, disposable-profile diagnostics,
   real reversible backup/restore/restart, installed-file comparison.
8. **Artwork and release**: original icon/thumb, repository build, public
   metadata/package/hash verification and documentation.

Every phase ends with a clean commit, pushed branch, recorded validation and a
usage-limit check. Work continues automatically only when the next phase fits
within a conservative remaining-usage buffer.

## Release acceptance criteria

- Automated tests cover happy paths, unsafe paths, exclusions, interrupted
  restore, rollback, malformed pending state and failed verification.
- Python compilation and Git whitespace checks pass.
- Package has one correct top-level add-on directory, valid XML, no tests, Git
  files, bytecode, reports or macOS AppleDouble metadata, and passes ZIP CRC and
  SHA-256 checks.
- Exact packaged ZIP passes native Kodi checks in a disposable Mac profile.
- A reversible AF3 backup/restore/restart proves persistent settings and helper
  data on the Mac.
- Installed files match the package byte for byte.
- `repository.eengert` metadata, MD5, ZIP download and repository SHA-256 are
  verified after publication.
- Release notes state that Apple TV/tvOS remains unvalidated.
